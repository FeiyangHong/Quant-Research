# 数据合同

版本：v0.1；制定日期：2026-11-14；项目时区：Asia/Shanghai。

本文件规定可进入研究、回测和未来模拟执行的数据条件。供应商具备某接口不代表本项目已经获得或审计该数据。本轮尚未下载研究样本、完成供应商验收或产生策略回测结果。

关联文件：[研究范围](RESEARCH_BRIEF.md)、[策略定义](STRATEGY_SPEC.md)、[实验计划](EXPERIMENT_PLAN.md)、[风险政策](RISK_POLICY.md)、[供应商证据](../evidence/DATA_SOURCES.md)、[实施状态](IMPLEMENTATION_STATUS.md)。本文件负责数据含义与可用时点；策略参数和样本划分由对应文档负责。

## 1 范围和阻断原则

研究数据允许包含上海主板、深圳主板、创业板、科创板、北交所及相关指数、ETF和外生市场。研究可用、账户可交易、代理工具可交易是不同字段，不能互相推导。

优先获取2010年以来的历史；首轮确认性回测从2016-01-01之后、相关数据和历史规则均可通过验收的区间开始。2010–2015可作制度和探索研究，缺少完整费用/规则时不得偷用当前费率产生确认性可交易结论。最近期间截止于完整数据已验证的交易日，不能以网页“最新”标签代替完整性检查。

数据使用门槛按研究方向拆分：

|方向|最低数据依赖|缺失时的处理|
|---|---|---|
|R1 ETF轮动与简单风险控制|ETF证券主表、历史上市/退市、原始日行情、基金分红/份额变化、日历、历史交易规则、费用、指数定义与可比收益|价格和规则合格后可先行；不借用缺失的财务/新闻数据|
|R2 价值盈利质量|R1通用交易层，加股票PIT财务及修订链、历史股本/市值、历史行业、状态和公司行为|财务PIT不过，只阻断依赖该字段的确认性研究；可以继续R1|
|R3 反转与交易行为|股票原始行情、复权/公司行为、历史可交易池、停牌/涨跌停、流动性；若使用分钟执行则另需分钟数据|缺分钟/盘口时，不把日线模拟升级为已验证的成交模型|
|R4 PIT事件|真实发布时间及版本化公告、事件内容、必要的一致预期历史快照、行业/证券映射|事件首发或所使用预期基准的历史版本不清楚时只做描述/探索，不能报告确认性事件Alpha|

宏观、资金、分析师和新闻数据均为单独受审的数据集，不因R1通过而自动通过。

## 2 三种历史可得性模式

每个数据集和每个实验必须声明以下模式之一：

|模式|含义|可以声称什么|
|---|---|---|
|`historical_public_asof`|依据当时公开文件和可验证发布时点重建；使用明确保守延时|公开信息口径的历史可用性；不声称本项目当时或供应商当时实际收到|
|`historical_vendor_asof`|保存或购买了可核实的供应商历史首可用时间、修订版本|该供应商通道的历史可用性；仍需验证覆盖和时间语义|
|`live_capture`|从项目开始实时记录公开、供应商返回、接收和处理时间|本系统在实际运行中的收到时点和内容|

今天下载历史记录的时间仅是`ingested_at`，不是历史`vendor_first_seen_at`。供应商今日回填行的创建时间也不自动等于当年首可用时间。缺失历史时间不得伪造，必须降为公开时点重建、增加延时或阻断对应研究。

混合不同模式时必须逐字段记录，并在实验manifest标注最弱模式及缺口。不能把一个数据集有PIT能力推广成整套研究具备完整PIT。

## 3 决策时钟

默认决策截止为每个交易日21:00（Asia/Shanghai），最早在下一交易日的预先规定执行窗口成交。执行窗口、价格模型及未成交处理由策略和实验文件规定。

- 只允许`available_at <= decision_cutoff`的记录进入当次信号。
- 有可靠时分秒的记录：按对应模式，以公开可得/供应商可得/实际接收和处理完成时间中适用的最晚值为下界，并计入预先声明的处理延时。
- **只有公告日期D而无可靠时间：保守设置为D之后第一个交易日21:00可用，再下一交易日才允许执行。** 不臆造D日盘前或收盘前可用性；对该默认再做增加一个交易日的延迟压力测试。
- 供应商标注日期不等于公开日期。两者不一致时保留原字段并解释，不擅自选较早值。
- 21:00之后公布的精确时间记录进入后续截止时点；非交易日公告按下一次合格决策时钟处理。
- 海外价格、汇率、公告和宏观输入统一换算时区，处理夏令时。北京时间当日21:00尚未收盘的海外市场，不得使用其“同一日期”的最终收盘值。
- 采用训练标签时，标签完成时间必须早于模型拟合截止；未来收益只允许进入标签列，不允许进入特征或股票池筛选。

日行情价格形成、供应商发布、因子计算、订单生成和成交是五个不同事件。禁止用收盘后完整成交量/财报/ETF份额构造信号后假设同一收盘价成交。

## 4 通用记录与数据类型

金额、数量、时间、主键不可由模糊列名推断。每个表随附schema版本和字段字典。

|字段|类型/约束|含义|
|---|---|---|
|`dataset_id`, `schema_version`|非空字符串|数据集及解释规则版本|
|`instrument_id`|内部不变字符串|证券身份；不把当前六位代码当全部历史身份|
|`exchange`, `symbol`, `symbol_valid_from`, `symbol_valid_to`|字符串、时间|交易所和历史代码映射；代码变更可追溯|
|`event_time`, `period_end`|带时区时间/日期，可按表为空|交易或经济归属期，不能替代可用时间|
|`published_at`, `public_at`|带时区时间；仅保留一个规范名|规范名使用`published_at`；`public_at`只能作供应商映射别名|
|`publication_precision`|枚举|`second` / `minute` / `date_only` / `unknown`|
|`vendor_first_seen_at`|可空带时区时间|供应商历史首次可提供时间；未知必须为空|
|`ingested_at`, `processed_at`|非空带时区时间|本项目接收与处理完成时间|
|`available_at`, `availability_mode`|非空时间及上节枚举|该实验实际允许使用的时点与证据模式|
|`revision_id`, `supersedes_id`|字符串、后者可空|版本关系；更正不能覆盖旧值|
|`effective_from`, `effective_to`|带时区时间/日期|制度、成员或状态的经济生效区间|
|`source`, `endpoint`, `source_record_id`|字符串|供应商、接口与原始记录身份|
|`source_url`, `document_hash`, `raw_object_hash`|可空URL/哈希，按表必需|原文追溯和不可变快照|
|`value`, `unit`, `currency`|按schema指定|数值及单位；缺失不是0|
|`quality_status`, `quality_reason`|枚举与说明|`accepted` / `quarantined` / `missing` / `provisional`|
|`license_profile_id`|非空字符串|数据许可和存储/使用范围版本|

存储使用可表达时区的时间戳；计算与展示明确Asia/Shanghai。不能把没有时区的时间默认当UTC或本地时间。历史更正同时具有“经济属于哪个时期”和“何时获知这个更正”两条时间轴。

复合主键按表定义，例如财报至少包含`instrument_id + statement_type + period_end + report_scope + revision_id`；行情至少包含`instrument_id + venue + interval_start + frequency + revision_id`。相同主键冲突不得静默去重。

## 5 核心数据表

### 5.1 证券主表及三个Universe

证券主表含上市/退市日期、证券类型、交易所、历史板块、币种、最小报价单位、基金类别、跟踪指数和历史代码。基金上市日期、清盘/合并/终止上市事件也必须保留；不能只用今天存活ETF。

Universe分别记录：

- `research_eligible`：研究范围和数据条件。
- `account_tradable`：账户权限、产品资格、当日状态及人工确认记录。
- `proxy_eligible`：代理工具许可、跟踪对象、费用、流动性、偏离和替代关系。

科创板个股默认不在账户可交易集合。创业板和北交所权限未核验时不能根据用户研究兴趣自动启用。能够交易某ETF不意味着能够交易其成分股；能研究其成分股也不意味着该ETF合格。

回测中的Universe用当时已知的上市、行业、风险状态和事前流动性信息形成。退市或ST之后仍然持有的仓位必须进入账本，不能通过重新筛池使损失消失。

### 5.2 原始行情与流动性

保存未复权OHLC、前收盘/除权参考价、成交量、成交额、交易状态、涨跌停价及其来源。字段字典统一成交量为股/基金份额、成交额为人民币元；供应商以手、千股、万元返回时显式转换并保留原单位。

零成交、停牌、缺记录和采集失败是不同状态。价格不能以无限期前填充伪装成可成交；持仓估值允许用明示的滞后估值政策，但同时标记价格陈旧天数。

日线只能支持日线层级的成交假设。开盘在涨停价、全天一字板或开盘跌停时是否成交必须保守模拟；日内曾出现非涨停价不证明本订单排队成功。没有分钟数据不能把全天成交额当某个分钟窗口容量。

历史成交量/平均成交额可供事前下单预算；当日最终总量只能用于事后成交上限检查或明示的执行模拟，不能泄漏进早于收盘的订单决策。

### 5.3 公司行为与现金账

保存现金分红、送股/转增、拆合股、配股、合并换股、要约、退市处理等事件的公告、登记、除权、到账、生效日期，以及现金/股数转换规则。

原始成交价用于买卖、整手、涨跌停和费用。收益计算用明确的总收益口径或公司行为账本，但不能同时使用已含分红的收益价格再重复记入现金分红。现金分红在可支配到账时记入现金；红利税按适用历史规则及真实持有批次处理。

复权序列仅服务于规定的特征/收益用途。保存复权因子、计算方法和查询参考日；不能把复权后的价格拿去模拟交易。不能笼统认为所有后加统一比例复权都会泄漏收益率，也不能忽略它对绝对价格、股数和量价阈值的影响。

基金市场价、单位净值、累计净值、复权净值、基金份额和折溢价分别保存。计算基金费用时检查价格/净值中已体现的持续费用，避免重复扣除；代理ETF的跟踪偏离独立报告。

### 5.4 财报与衍生财务

原始三大表保留首发、补充、更正、比较报表重述及合并/母公司口径。`period_end`、`published_at`、`available_at`分别存储。

TTM、同比、单季度、ROE、盈利收益率等由当时可用版本计算，记录输入revision IDs。处理累计流量表与单季数据的区别，资产负债表存量不能机械相减当流量。金融企业和非金融企业的科目不能无说明地替换。

缺失、负分母、零分母、报表过旧和缺乏可比前期需有专门标记。缺失处理、行业内标准化和中性化由策略定义，但其输入都必须通过PIT合同。

### 5.5 行业、指数、主题

每条成员关系包含分类体系与版本、证券身份、公告时间、经济生效区间、历史可用模式。分类体系修订本身也是事件；不能直接把当前申万行业映射到全部过去。

指数成分公告日和生效日分别记录。月度成分快照只证明快照日状态，不能补出未观察的调入调出日期。价格指数、全收益指数、净收益指数和可交易ETF价格不能混用而不调整比较口径。

主题数据需保留当时定义、命名、成员和首次可得时间；今天的概念名单不能回填历史。无法获得历史版本时，允许从项目开始做前瞻记录，不允许确认性回测“过去主题轮动”。

### 5.6 公告、新闻与一致预期

保留公告原文、标题、发布时间精度、附件哈希、更正关系、首次抓取、实体映射和事件抽取模型版本。转载时间、页面修改时间、原始发布日期不是同一个字段。

分析师数据需有报告发布时刻、预测针对的财年、机构/分析师身份、预测值、有效期、撤回/修订版本和当时可用的一致预期计算成员。用今天的一致预期历史图回填过去不自动满足PIT。

“超预期”必须相对事件前已可得的基准；只有实际业绩而无可靠预期，不能把增长称为预期差。LLM/文本模型使用的训练年代与外部知识能力另行登记，不能凭模型今天知道的事件结局构造旧标签或主题。

### 5.7 宏观、政策和跨市场

宏观数据保存经济归属期、首次发布时间、数据vintage、修订发布时间及实际可用模式。发布日历是计划，实际发布时间需核实。当前数据库修订后的历史值不得冒充当年首发值。

政策文本记录首个可核实公开时间与生效时间；政策“强弱/利好”标签规则在研究前固定并版本化。无法重建历史vintage时只用可追溯子样本或做前瞻采集。

跨市场日历、收盘时刻、休市、汇率基准时间和夏令时入表。市场日期相同不表示信息当时可得。

### 5.8 资金与拥挤

ETF份额变化不直接等同二级市场净买入，需剔除拆合份额等事件并记录发布日期。融资融券、机构持仓、基金季报等按披露时间而非持仓截止日期使用。

供应商“主力资金流”必须记录按成交大小/方向推算的具体算法，不能当作可识别机构的真实净现金流；算法或披露制度改变需版本化。缺少可追溯定义的指标不得进入主检验。

## 6 规则、权限与费用表

历史规则按交易所、证券类型、板块、状态、交易日期、上市阶段区分，并包含公告/生效/失效日期、规则来源和规则ID。至少覆盖T+1及卖出可用股数、买卖单位、最小报价单位、涨跌幅、上市初期和退市整理特殊规则、停复牌、订单有效性。

历史费用分别保存佣金比例、最低收费、是否含经手/监管费用、印花税、过户费、产品豁免与生效日期。某账户今日优惠费率不能无说明地回填全历史；另可提供“以今天账户交易这些历史路径”的反事实成本情景，但不能冒充历史实得收益。

A股最低5元佣金有官方历史通知依据；本项目按保守规则建模，各产品/账户以合法现行费表核验。任何已含规费不能重复叠加。费用金额舍入、最低收费的委托/成交聚合单位、拆单合单规则均需匹配收费表；不能向同一委托的每条fill重复收最低费用。

账户权限记录核验时间、证据和允许产品；未知视为不能新增订单。研究阶段不接入自动实盘，不在数据仓库存放交易密码。规则冲突或缺失时隔离对应时期/证券，不能“默认10%”“默认可成交”或删掉困难样本后继续报告。

## 7 数据验收

供应商验收结果必须独立于策略收益。使用困难样本和按年代/板块随机抽样，两种抽样记录分别保留。

|检查|验收要求|失败处理|
|---|---|---|
|schema/主键/单位|必需字段完整、主键无未解释冲突、单位转换可追溯|隔离失败分区，禁止静默去重/填零|
|时间和修订|原始发布、更正发布与as_of查询一致；日期精度遵守保守时钟|阻断相关PIT研究|
|前缀不变性|在T截断数据再计算，与加入T之后数据时的T前结果一致|定位未来值、成员、缩放或修订覆盖；修复后重跑|
|退市与成员|历史退出证券、基金和持仓不丢失；成员调整公告/生效可核|禁止确认性可交易结论|
|公司行为|股数、成本、现金、估值在事件前后守恒，可与原公告/对账核验|隔离事件及受影响策略|
|双源对账|分层核验原始价格、量额、公司行为；误差按字段/最小报价单位解释|未知差异不按对收益有利的来源选择|
|覆盖率|按年月、板块、状态、字段统计；新股/退市/极端日单独报告|不能只报告总体高覆盖率|
|发布时间/延迟|日常任务在21:00前完整数据有证据；过期/迟到可识别|当次保持安全持仓/停止新增订单，记录原因|
|授权|允许的个人研究/自动化/托管/导出/存储/共享和到期处理明确|使用合规替代源；仅阻断不合格用途|

数据前缀不变性测试针对当时可用版本和信号；供应商后来纠正真实历史错误时建立新数据版本，并分别保留旧实验与重跑结果，不能偷偷替换历史快照。

## 8 交付物与版本化
