# 离线日线账簿 MVP

状态：`DAILY_SCREEN_ONLY`。实现为 `src/quant_research/execution.py`，不是券商接口或真实开盘排队模型；人工合成数据结果只用于工程验收。

## API 与时钟

`run_backtest(dataset, decisions, initial_cash, cost_multiplier=1, slippage_multiplier=1, max_sell_attempts=5, tax_rules=None, start_date=None)` 返回 DataFrame：`nav`、`positions`、`orders`、`fills`、`rejected_orders`、`costs`、`exposure`、`cash_events`、`order_events`、`rights`，以及模式和限制说明。

每个决策有 `decision_date`、后续交易日的 `execution_date`、`weights`、`reference_prices`、`adv20`。可选 `decision_at` 必须为北京时间21:00。参考价必须等于当时可见原始收盘价。引擎独立重算当时可见20交易日平均成交额，容量不得超过调用方与引擎历史值的较小者。允许预先指定额外执行延迟；禁止同日或倒序执行。

`start_date` 保留完整历史供信号和ADV暖启动，同时使账户从指定期间以新现金开始；此前成交与股息权益不继承。期间前已经形成、期间内执行的决策可以使用。

## 委托、风控与成交

1. 21:00以原始参考价及账户权益计算整手目标；原始委托按追加方式保留，不根据最终成交价改写目标。主板、创业板个股属于可核验范围；科创板和北交所个股拒单。ETF产品权限独立检查。这里只支持100份/股买入单位、明确tick及T+0/T+1；股票只支持T+1。
2. 执行日先处理实际卖出，再验买单。未成交卖单不释放现金或持仓风险。逐笔买单验收和撮合串行发生；已成交新增仓位进入下一笔验单，不存在绕过检查的并发买入保留量。原始未验收买入意图不能当作已获风险额度的委托。
3. 买单用原始参考价加不利滑点、向不利方向对齐tick形成现金预留；预留/解冻事件保存总现金、可用现金。成交跳空只能减少股数，不能增加原始目标或突破该笔预留。单ETF35%、单股5%、股票行业20%、总敞口100%及现金约束联合覆盖旧仓、锁仓及新增成交；成交后再按真实费用精确复核。被动超限保留并报告。
4. 日线拟合价为开盘价加ETF每边3bp/股票每边10bp研究滑点。向不利方向对齐tick后必须仍在真实涨跌停价及当日日线高低范围内，否则拒单，不裁剪价格制造成交。停牌、无量、缺行情/限制规则、开盘处在买方涨停或卖方跌停均不成交。高低范围仅为事后合法性筛查，不代表拥有日内成交信息。
5. M8正确性修复后，同一证券同日全部买卖按绝对量共享三项上限：已知历史ADV20金额的1%、实际日成交额的1%、实际日成交份额的1%，取剩余额度最小值后执行整手/现金/交易规则。历史金额按参考价与模拟价中较高者保守消耗；实际量额仅限制事后撮合，不改事前订单，缺失或无效不能当无限容量。`DAILY_CAPACITY`保留请求、允许、实际数量及三项累计消耗。日线上界仍不能证明开盘队列容量。买单未成交余额当日作废；卖单剩余量生成有父订单ID的新日委托，最多合计5次尝试，随后报警并保留持仓。跨日真实委托各自计最低费用。旧结果仅保留并作只读影响扫描，未重放。
6. 卖出按历史买入批次检查可卖日期，未解锁股份仍计全部风险和估值。卖出回款当日可交易，次交易日可取。当前MVP没有提款操作；可取现金为保守账簿数值。

## 费用与公司行为边界

佣金是统一研究情景：成交金额3bp、每笔实际日委托最低5元，包含约定规费。`cost_multiplier` 只放大佣金；`slippage_multiplier` 独立放大滑点。ETF不套用股票印花税和过户费。股票必须传入有 `effective_from`、`effective_to`、`stamp_duty_sell`、`transfer_fee_both`、`verified=True`、`source_url` 的唯一适用税费记录；没有内建推定法定税率。调用方须对核验记录负责；缺失、重叠或无来源拒单。法定税费不参与倍数压力。

ETF现金股息按明确登记日收盘持仓在除息日记应收，支付日转现金；登记日后卖出仍保留应收权利，登记日后买入不获得旧股息。缺失或无效登记日阻断。原始价格计持仓，TR指数不进入资金账，避免重复分红。拆合份额按下述发行人明确取整规则处理；没有明确取整或现金补偿条款时仍阻断，不能默认舍掉零股或假定回款。单独的交易所退市事件仍保留零估值权利；清算回款必须用下述关联清算事件，不能把正回收率直接塞入 `DELISTING`。股息/盘前拆分生效日旧订单明确撤销，买单不追补，卖单按调整后的持仓及次日参考价重试。生效后修订若改变公司行为条款，因尚无修正账机制而阻断，不追溯改写历史。

### 份额折算：账户取整、时点与原始报价口径

规范化 `SPLIT` 字段如下；公告、提醒、结果与取消公告仍由数据层保留完整来源链，不能把每份公告当作一次额外折算。

| 字段 | 约束 |
|---|---|
| `effective_phase` | `BOD`：开盘前；`EOD`：当日交易及原始收盘估值之后、21:00决策之前。缺省仅兼容旧样例的BOD |
| `rounding_policy` | `EXACT`：只接受账户合计为整数；`FLOOR`/`CEIL`：按官方条款向下/向上取整一次 |
| `record_date` | 显式取整事件的BOD要求前一交易日；EOD要求当日，确保持有人边界一致 |
| `action_status` | `CONFIRMED`执行；已在生效边界前核验的`CANCELLED`仅留审计，不改变持仓或阻断正常交易 |
| `terms_verified`, `source_url` | FLOOR/CEIL及取消事件必须有核验标记和来源 |

账户先按Decimal计算 `sum(各批次份额) × share_factor`，只对总额做一次发行人取整。不能对每个交易批次分别向上/向下取整，否则会制造或吞掉份额。内部批次分配先取各批次整数部分，再把账户总额要求的剩余整数优先分给解锁最晚的批次；原购入日和可卖日期保留。该保守分配避免折算提前解锁T+1份额，不声称还原登记机构的逐批次税务分配。分数归基金或由基金承担的经济差额在 `share_events.rounding_share_delta/rounding_value_delta` 中明确显示，不虚构现金补偿。

BOD先转份额再处理当日交易；EOD允许当日正常买卖，并对成交后的账户持有量转换。EOD当日原始收盘价仍是旧份额口径，因此转换后估值为原始收盘价除以比例，不能把新份额乘旧收盘价。停牌/零成交日的旧报价不能覆盖这项已知调整；引擎保留经折算调整的上次有效估值并报告陈旧天数，待下一有效交易报价更新。

21:00目标同样使用当时已经发生的份额口径。输入仍以当时可见原始收盘价校验，订单另存 `source_reference_price`，实际份额预算和现金预留用转换后的 `reference_price`，并存 `reference_basis=POST_EOD_ADJUSTED`；停牌旧报价使用 `CARRIED_ACTION_ADJUSTED_MARK`。历史ADV为人民币金额，不随折算倍增。待执行旧单位订单显式撤销；卖单按新持仓重新生成有父ID的指令，买单不补单。已有不足100份的余量可以在可卖时整笔卖出，买入仍须100份整手。

实际困难样本的时序保持原样：510500的2022-08-26是EOD、比例1.14539、账户CEIL；当日可交易，暂停的是约定购回业务，不能据此伪造ETF停牌。512100的2022-09-02是停牌日BOD、比例0.36555、账户CEIL，9月5日复牌；原拟8月3日的计划已取消，不能再执行。[510500 2022-08-23折算公告](https://www.sse.com.cn/disclosure/fund/announcement/c/new/2022-08-23/510500_20220823_1_aMMa3ZNB.pdf)；512100的取消与重新实施来源保存在 `reports/real_data_phase3/event_manifest.json`。

510500的2015-04-14折算保留原经济日期。预告公式为 `(X/Y)/(I/1000)`，其中基金资产净值、总份额和指数收盘值不能由后来结果反填；最终0.28032483在4月15日公告中确认，按日期精度规则还须延迟可用。若模拟账户当时实际持仓而确切比例在生效边界后才可知，引擎以 `UNKNOWN_SPLIT_TERMS_AT_EFFECTIVE_TIME` 阻断估值，不以停牌为理由偷用未来比例。[2015-04-03预告](https://www.sse.com.cn/disclosure/fund/announcement/c/2015-04-03/510500_20150403_1.pdf)、[2015-04-15结果](https://www.sse.com.cn/disclosure/fund/announcement/c/2015-04-15/510500_20150415_2.pdf)。

2016年开始的新账户在该2015事件中没有持仓：前置SPLIT/现金股息仅记录 `UNOWNED_PRE_ACCOUNT_EVENT`，不要求此前存在账户现金或持仓，不把该事件删掉或移到别日。数据层仍须独立保证TR暖启动仅在条款获知后使用。活跃期无持仓但条款尚未可知的证券记 `UNOWNED_TERMS_PENDING`，获知之前不接受新买入。本实现没有声称能给持有未知比例权利的账户生成完整可信净值。

`tests/test_share_events.py` 覆盖账户跨批次取整、T+1、EOD当日交易及次日目标金额、原始价格口径、停牌旧报价、零股整笔退出、取消计划、延迟公布比例、暖启动与前缀不变性。`share_events` 是追加式份额审计表，不是现金流水，不应再次计入NAV。

### ETF清算：份额、权利、应收与现金分离

`LIQUIDATION` 在 `ex_date` 将活跃交易份额账转换为清算权利账，取消该证券的全部待执行订单，并按先前 `record_date` 收盘持有量建立 `rights`。该日期是会计转换日期，不声明基金份额已在法律上灭失。登记日必须早于转换日；基金停止运作、清算开始、持有人登记及交易所终止上市是不同日期，不能互换。登记日后已卖出的持有人仍取得登记权利；登记日后的买入不增加该笔权利。`positions.quantity` 归零，原交易份额留在 `retired_quantity`，不再复活或重新买入。

金额未知时权利状态为 `UNPRICED_RIGHT`，账面价值保守记0并设置 `valuation_uncertainty=true`，这不表示最终回收为0。仅当金额在当时已可知，才允许通过独立的 `LIQUIDATION_PAYMENT` 增加应收款。两类事件均要求 `terms_verified=true`、非空 `source_url`，且 `available_at` 不晚于事件生效日开盘。引擎不根据后来发布的公告伪造提前可得的金额。

付款事件字段：

| 字段 | 含义 |
|---|---|
| `entitlement_action_id` | 对应 `LIQUIDATION.action_id` |
| `installment_id` | 官方分期的稳定标识，与权利ID组合唯一 |
| `recognition_date` | 金额首次允许入账的交易日，必须等于该事件 `ex_date` |
| `cash_per_share` | 本期增量回款/原登记份额，不是累计回款 |
| `pay_date` | 经核验的账户现金可用日期；不能把托管划款日自动当到账日 |
| `cash_settlement_verified` | `SCHEDULED`/`LATE_RECOGNITION` 必须为true，独立于分配金额条款核验 |
| `is_final` | 明确布尔值，是否最后一期；确认最后一期后拒绝额外付款 |
| `settlement_mode` | `SCHEDULED`、显式 `LATE_RECOGNITION` 或仅敏感性重放的 `ASSUMED_SCHEDULED_CREDIT` |

同日先建立清算权利，再确认付款，最后处理交易所退市。确认日增加应收，支付日将应收转为现金；非交易日支付只能在随后第一个账户会话反映。实际交易所退市早于或晚于清算款支付均不会二次注销应收或二次付款。`rights` 保留登记数量、注销数量、累计确认额、累计付款和未收余额；其 `carrying_value` 是已包括在NAV应收款内的追踪值，不能额外加到NAV。

只有当付款已发生后才获得公告时，`SCHEDULED` 阻断；显式 `LATE_RECOGNITION` 可以在获知日记录应收并收款，保留经核验原 `actual_pay_date`，同时将净值路径标记 `OBSERVATION_TIME_REPLAY`。这种保守观察重放不是实际现金到账时间线，不能用于确认性结论。

清算事件仅提供计划发放日、缺少经核验的适用账户结算规则且实际到账未核验时，只能用 `ASSUMED_SCHEDULED_CREDIT` 做事件敏感性重放。该模式的 `pay_date` 仅作假设日期，输出记录为 `scheduled_pay_date`，`actual_pay_date` 始终为空；相应净值及权利永久保留假设结算标记。存在未定价权利、迟到入账或假设到账时 `accounting_timing_eligible=false`。假设模式不具备真实数据确认资格；本日线模型的 `confirmation_eligible` 本来也始终为false。

512320的官方分配公告给出2024-03-29登记、每份0.77524元的分配条款以及2024-04-08资金发放日，但实际到账时间以销售机构为准。仅有该公告不能把4月8日标为已核验的账户现金时间。日期精度只有日时，先应用项目的保守可用时间规则；按3月29日收盘登记权利，4月1日可作为份额到应收款的会计转换日，它不是法律注销日或4月16日交易所终止上市日。[上交所2024-03-28清算财产分配公告](https://www.sse.com.cn/disclosure/fund/announcement/c/new/2024-03-28/512320_20240328_QIII.pdf)

每日21:00独立检查持仓资格、风险状态及已知退市公告，在下个合法窗口发起风险卖单，不等月度调仓。既有卖单按数量/日期复用或明确撤换，取消冲突买单；五次退出失败后保留持仓和警报，不每日重置重试次数。丧失买入资格不妨碍合法风险减仓；股票买入必须有明确正常状态，未知状态拒绝。

股票持有期红利税/追扣、股票清算、配股、换股、要约及无证据的零碎份额补偿仍未实现，出现相关场景阻断，不造收益。行情缺失的已有持仓保留最后明示估值并报告陈旧天数；已知退市估值为0。缺少ETF历史成分时仅报告直接仓位和股票行业，不能声称已核验ETF穿透行业风险。

每日恒等式：`NAV = cash_total + holdings_value + receivables`。模拟成交费用即刻结清，无隐含应付税费；不能表示的税费事件阻断。预留现金仍属总现金，不减少NAV。`orders` 是不可覆盖的原始意图表，生命周期/预留写 `order_events`，成交写 `fills`，拒绝和未成交余额写 `rejected_orders`。委托状态由这些事件重建。

## 真实数据的规则化普通分红与份额事件

`RULE_BASED_SIMULATION`仅在逐事件原始公告、当时有效规则及账户假设均通过独立核验时使用。`scheduled_pay_date`、`participant_transfer_date`、`modeled_cash_date`与`actual_pay_date`分开；实际到账仍为空。普通上海分红采用公告明确的指定交易账户可领取日。159922的2024年分红采用深圳参与人划付后的下一交易日2024-12-05为模拟可用日，假设正常划款及券商处理，并不保证这是实际到账日或最迟日。现金延迟另按0/1/3交易日注册全矩阵压力。清算不能继承普通分红规则。

份额折算依公告指定BOD/EOD处理，对账户登记总份额一次按FLOOR或CEIL取整，保留T+1锁仓分配。EOD折算先执行当日交易再变更份额与估值单位；次日停牌旧单位报价不得覆盖调整后估值。159922在2024-11-29收市后2.5倍折算，随后股息按折算后登记单位确认一次。上市前折算只保留元数据，不能对已按新单位上市的价格再次折算；512100已取消旧计划保留原始证据但不入账。
