## Unified master state

`src/quant_research/temporal.py` is shared by data lookup, strategy master snapshots, execution, and master schema audit. A row must be published by the query cutoff and effective at that cutoff. Current supported effective bounds are explicit ISO dates, interpreted as exchange dates in Asia/Shanghai; naive/aware intraday effective timestamp strings are **unsupported and rejected**, never truncated. Bounds use the existing strategy convention **[effective_from, effective_to)**. Missing bounds are unbounded, start is included, end excluded, and a timezone-aware query is converted to exchange time.

Among known states, the latest effective start wins; publication order resolves revisions of that state. Selection precedes checking its end, so an expired successor does not revive a formerly unbounded predecessor. A correction to an older interval does not erase a newer interval. `supersedes_id` supports existing lifecycle links: a strictly later start is a transition whose supersession activates only at that start. Same/earlier start is a correction; a correction intentionally moving the start later must explicitly set `revision_kind=CORRECTION`. Such a correction can leave an unknown interval. Corrections have stable identities, earlier predecessors and no branching correction chain. Visible same-start/same-publication conflicts, duplicate identities, invalid lineage and reversed/empty intervals fail closed. Separate effective intervals can be announced together. The instruments audit uses this same selector rather than requiring one original row per instrument regardless of interval.

Unknown/expired current state blocks both new buys and sales requiring unverifiable rules. Existing quantities remain recorded, current exposure uses an UNKNOWN bucket, and valuation is flagged uncertain. A currently effective permission revocation still permits a defensive sale when the current settlement, tick, fees and prices are verifiable. Ordinary blocked exits retain their shares and use the existing bounded retry behavior.

Standalone ETF and stock DELISTING now preserve all shares, carry zero as a conservative unknown mark, emit an `UNPRICED_DELISTED_RIGHT` row and set valuation uncertainty. Zero carrying value is not a finding that legal rights or future recovery are zero. No recovery cash is created.

## Main-ledger engineering integration

`run_backtest(..., engineering_replay=True)` connects the existing FIFO dividend-tax component to the actual main cash, positions, fees, rights and NAV ledger. It requires an explicit synthetic manifest, the engineering purpose tag and the reviewed taxpayer. The entry rejects manifests without the required synthetic declaration and engineering purpose; it does not independently authenticate arbitrary input origins. The normal runner continues to block stock dividends. No real file or event was relabeled synthetic in this work. Every emitted engineering table has `purpose=ENGINEERING_REPLAY_NOT_STRATEGY_PERFORMANCE` and `synthetic=true`.

The fixed-position entry supplies integer share targets independent of prices/signals; usual cash, lot, T+1, capacity and exposure checks still apply. Historical limit validation uses board, date, historical ST flag, IPO regime/session ordinal, a separately dated rule/reference attestation, decimal tick rounding and supplied raw limits. Unbounded IPO sessions, unsupported special sessions, unknown rules and wrong limit prices cannot fill. Dated statutory fees are charged on the execution day and now require a publication timestamp in engineering replay, including synthetic fixtures. Integrated tests cover MAIN/ChiNext in 2016, the 2020 reform, and 2024; existing tests cover the 2022 transfer-fee and 2023 stamp-duty boundaries.

Additional independent review reproduced four input-contract failures after the initial implementation (`work/m4_independent/pre_fix_counterexamples.txt`). Fixed targets with empty weight mappings were silently omitted; the same normal-runner input evaded rejection; linked corrections with missing/empty child revision identity were accepted. These are repaired: fixed mappings are validated before date filtering or instrument iteration, fixed keys drive lookup even without weights, normal-runner use rejects unconditionally, and every lineage link requires stable parent/child identities. Unlinked unversioned synthetic rows remain supported. The reviewer-authored tests were not modified by the execution author.

One further independent counterexample (`work/m4_independent/pre_fix_revision_kind.txt`) showed an explicit misspelled revision kind silently falling back to transition inference. The selector now validates the optional enum: missing/null retains inference; `CORRECTION` is explicit; `TRANSITION` requires a strictly later effective start. Any other explicit value fails closed.

Ordinary and explicitly classified special cash dividends capture FIFO claims after record-date trading; original entitled shares remain after disposal. Claims can be reserved at the terminal record close even when ex-date/payment lie after the replay window. Ex-date receivables and modeled pay-date cash are separate. Sales accrue a tax payable; only an explicit separately supplied modeled debit reduces actual cash. No modeled date is reported as an observed account debit. Pending payable is deducted exactly once from NAV. Potential holding-period tax reserves restrict available/withdrawable cash but are not a second expense. Hypothetical liquidation NAV deducts potential tax in addition to accrued payable, without double counting. The record-close reserve uses a hypothetical next calendar-day disposal solely to bound tax exposure; it is not an assertion of a verified next tradable session or realizable sale proceeds.

The replay verifies main-ledger versus FIFO quantities including the zero-tax-lot case, and emits daily tax balances, immutable claims, FIFO lots and tax events. Existing bonus/share conversion, rights issue, merger and stock liquidation/payment cases remain fail-closed where classification/implementation is missing. This does **not** complete all real corporate-action dependencies.

## Reproducible reconciliation

Run `.venv\Scripts\python.exe scripts/replay_equity_engineering.py`. Six fixtures cover MAIN and ChiNext, each with ordinary+special dividends, a five-attempt failed exit followed by a new verified exit instruction, or retained unknown delisted rights. Every price, security, calendar, permission, source URL and event attestation is invented. Weekday calendars are explicitly not official trading calendars. These 420 daily account rows are not market evidence.

`scripts/replay_equity_engineering.py:independent_expected` computes expected balances using fixed events and Decimal arithmetic without reading engine fills or using production accounting/rate functions. Two 200-share buys cost CNY2,005.02 each; 400 shares entitle CNY100 ordinary plus CNY300 special cash; sale gross CNY4,000 has CNY7.04 explicit fees; the ordinary exit accrues CNY80 tax and the later exit CNY40. Daily comparison checks quantities/sellability, cash, receivables, holdings value, payable, paid tax, reserve, available cash, NAV, hypothetical liquidation NAV, each dividend's immutable entitlement and unknown rights quantities. All six cases have zero reconciliation differences. Root-authored independent tests separately check daily main-ledger balances and temporal cases.

Each fixture has an exact input JSON, expected CSV and all ledger CSVs. `engineering_replay/provenance.json` records source classification, limitations, artifact SHA256 values and the implementation/test source hashes used to generate them. There are no annual returns, Sharpe ratios, alpha claims or optimization runs.

Validation: after the independent-review repairs, the focused accounting/independent-review suite passed **245 tests** in 6.25s, including all 16 external independent cases and 38 author M4-specific tests. A final nullable-kind normalization rerun passed all 54 external/author M4 cases. One pandas FutureWarning originates from the unchanged independent fixture. Strategy/data regression previously passed **48 tests**. The root integration report records the final whole-suite run. Prior reports and run artifacts were not changed.
